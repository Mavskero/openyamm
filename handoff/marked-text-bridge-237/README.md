# 237：组合文字显示与有序输入边界

UIKit原生输入框被隐藏，原提交算法已等待取消组合，但没有把尚未提交的文字传给游戏。本次通过持久SDL补丁补齐TEXT_EDITING；组合文字只用于显示，不提前写入答案、名字或银行金额。补丁由CMake在iOS依赖中检查和应用，保留既有scene-bounds补丁，不能匹配时明确失败。

保存名称、建队姓名、银行金额以`[preedit]`显示临时文字。选词期间的删除、确认和取消不修改已提交内容；实际提交后下一次真实回车立即有效。保存和银行在有效Confirm/Cancel事件处停止消费，同帧后到文字不会混进本次保存或金额。银行仍保留原10位ASCII金额过滤与实际交易规则，Escape只校验一次原Action113拒绝。

失焦、换槽、滚动、关闭、编辑对象切换和控制台会清理临时显示。控制台事件先隐藏显示，由排队的空Composition按顺序结束组合态，避免把此前IME退格变成真实删除。阻塞帧丢弃旧输入后再完整清理。建队与问题答案还补齐原有修饰键加V的粘贴入口，沿用原Unicode过滤和长度限制，组合期间等待提交。

UIKit保留原committedText差分、删除及64空格基线；组合清空先于真实删除/提交。取消组合没有通知时，受保护的unmark回调仍走同一差分路径，避免漏提交或双提交。选区从UIKit的UTF16单位换算为SDL字符数。系统隐藏键盘的StopTextInput在后端清理之后才关闭active，因此空组合事件能正常入队。这些是源码与构建结论，没有实际UIKit输入法或回调时序验收。
